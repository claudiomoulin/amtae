⚡ validarPagoUno

LWCQuick Action

Propósito: Ejecuta el flujo completo de cobro con tarjeta de crédito a través de la pasarela Pago Uno: valida la cuenta, tokeniza la tarjeta y realiza el cobro grupal. Si el monto no coincide exactamente, genera un ajuste.

Precondiciones

  • La Oportunidad debe tener Medio_de_Pago__c = 'Tarjeta' y Medio_Verificado__c = false.
  • Debe tener al menos un OpportunityLineItem (plan cotizado).
  • La Account vinculada debe pasar la validación de campos requeridos (accountValidate).
  • El BIN de la tarjeta ingresada debe existir en los registros de Medio_de_Cobro__c.

Flujo de ejecución

1. Al abrir: getDataOppForPU
2. accountValidate
3. Muestra formulario tarjeta
4. buscarMedioCobro (BIN lookup)
5. generarTokenPagoUno
6. ejecutarCobroGrupal
7. Si monto ≠ esperado → ejecutarAjustes
8. crearEntradaMedioCobro

Objetos y Campos

ObjetoCampos relevantes
OpportunityMedio_de_Pago__c, Medio_Verificado__c, Amount, Plan__c, AccountId, HasOpportunityLineItem
AccountFirstName, LastName, PersonEmail, CUIT_Titular__pc, Gender__pc, Cumpleanios__pc, BillingStreet, Ocupacion__c
Medio_de_Cobro__cNombre_banco__c, Code__c (BIN 6/4/2 dígitos)
Medio_de_Cobro_entry__cTipo__c='Tarjeta', Opportunity__c, Token__c, ExternalReference__c
MercadoPago__mdtMP_Amount__c (monto de validación)
Monto_Validacion_Pago_Uno__mdtMonto__c (monto de validación PU)

Clases Apex involucradas

⚡ validarMercadoPago

LWCQuick Action

Propósito: Crea una suscripción de débito automático en MercadoPago desde una Oportunidad. El componente valida el estado de la Opp y la cuenta antes de permitir el alta de la suscripción mensual.

Precondiciones

  • Medio_de_Pago__c = 'Mercado Pago' y Medio_Verificado__c = false.
  • StageName = 'Pendiente de Cierre'.
  • La Account debe pasar accountValidate (campos requeridos completos).
  • La Oportunidad debe tener al menos un producto (OpportunityLineItem).

Flujo de ejecución

1. Al abrir: getDataOppForMP
2. accountValidate
3. retornarFechaVigencia
4. Muestra formulario (nombre, monto, email, frecuencia)
5. crearSubscripcion → MP API
6. Actualiza Medio_Verificado__c

Objetos y Campos

ObjetoCampos relevantes
OpportunityMedio_de_Pago__c, Medio_Verificado__c, StageName, Amount, Plan__c, HasOpportunityLineItem
AccountEmail_MercadoPago__c (campo custom)
Medio_de_Cobro__cSubscriptionId__c, Monto__c, Name

⚡ botonValidarCBU

LWCQuick Action

Propósito: Valida un CBU contra un webservice externo comparando con el CUIT/CUIL del titular. Si la validación es exitosa, actualiza la Oportunidad como medio verificado y crea un registro Medio_de_Cobro_entry__c con los datos bancarios.

Precondiciones

  • Medio_de_Pago__c = 'CBU' y Medio_Verificado__c = false.
  • La Account asociada debe pasar accountValidate.
  • La Oportunidad debe tener al menos un producto cotizado.

Flujo de ejecución

1. Al abrir: getOportunidadInfo + accountValidate
2. Muestra formulario CBU (22 dígitos)
3. callWebService (CBU + CUIT)
4. Si COINCIDE → actualizarOportunidad
5. crearEntradaMedioCobro (CBU, CUIT)

Objetos y Campos

ObjetoCampos relevantes
OpportunityMedio_de_Pago__c, Medio_Verificado__c, HasOpportunityLineItem, AccountId
AccountCUIT_Titular__pc y todos los campos de accountValidate
Medio_de_Cobro_entry__cTipo__c='CBU', CBU__c, CUIT__c, Opportunity__c

⚡ convertirLeadLwc

LWC

Propósito: Convierte un Lead en Account + Contact + Opportunity con validaciones previas: verifica el estado del Lead, que el propietario no sea una cola, y que no exista ya una Account con el mismo DNI.

Validaciones

  • Status = 'Contactado' (requisito para convertir)
  • OwnerId no comienza con 00G (no puede ser una cola)
  • No existe Account con Numero_Documento__pc igual al Document_Number__c del Lead

Flujo

1. Wire Lead (Status, OwnerId, Document_Number__c)
2. Click Sí → valida estado y propietario
3. checkAccountIfExist (por DNI)
4. Si no existe → convertLead
5. Navega al Account creado

⚙ Clases Apex — MercadoPago

Conjunto de clases que gestiona la integración completa con la API de MercadoPago para cobros por débito automático (suscripciones).

validarMercadoPagoController

Controlador principal del componente LWC homónimo. Obtiene datos de la Oportunidad para pre-cargar el formulario de MP, valida fecha de vigencia y crea la suscripción.

  • getDataOppForMP(Id) — Consulta Opportunity con Account.Email_MercadoPago__c
  • retornarFechaVigencia(vigenciaDesde) — Calcula fecha de inicio de la suscripción
  • crearSubscripcion(...) — Crea la suscripción vía CrearSubscripcion.cls

CrearSubscripcion

Realiza el callout POST a la API de MP para crear la suscripción. Parsea la respuesta y actualiza Medio_Verificado__c y crea el registro Medio_de_Cobro__c.

CancelarSubscripcion

Envía solicitud de cancelación a MP (PUT con status=cancelled) y actualiza el registro en Salesforce.

BuscarXSubscripciones

Consulta el estado de una suscripción en MP por ID. Devuelve el estado actual (authorized, cancelled, pending, paused).

LlamarBuscarXSubscripciones / LlamarCancelarSubscripcion

Wrappers @AuraEnabled para exponer los métodos anteriores a LWC.

ActualizarTerminosController

Expone a LWC los métodos para leer y actualizar los términos de una suscripción (nombre, monto).

  • getNameYMontoSubscripcion(Id) — Lee desde SubscripcionSolicitud__c o Medio_de_Cobro__c
  • actualizarTerminos(name, monto, IdSubscripcion) — Llama a ActualizarSubscripcion vía @future

ActualizarSubscripcion

Clase con método @future(callout=true) que actualiza el precio del plan en la API de MP. Guarda un registro de auditoría en SubscripcionActualizacion__c.

CalloutControllerMercadoPago

Clase base para todas las llamadas HTTP a MP. Gestiona autenticación con MercadoPago__mdt (Access Token) y construye los encabezados de la petición.

MP_WebHooksTriggerHandler / MP_WebHooksTriggerCallout

Procesan las notificaciones webhook de MP (platform event). El handler identifica el tipo de evento (payment, subscription) y el callout consulta el estado actualizado en la API de MP para sincronizar con Salesforce.

NotificacionesMercadoPagoWs

REST Endpoint (@RestResource) que recibe los webhooks de MercadoPago via HTTP POST y publica un Platform Event para procesamiento asíncrono.

⚙ Clases Apex — Pago Uno

Conjunto de clases para la pasarela de pagos Pago Uno, usada principalmente para cobros con tarjeta de crédito desde el CRM.

ValidarPagoUnoController

Controlador principal del componente validarPagoUno. Coordina la búsqueda de datos de la Oportunidad, el lookup de BIN de tarjeta y los métodos de cobro.

  • getDataOppForPU(Id) — Consulta Opportunity + Account + OpportunityLineItem
  • buscarMedioCobro(bin) — Busca en Medio_de_Cobro__c por prefijos de 6, 4 o 2 dígitos del BIN
  • generarTokenPagoUno(body) — Delega en PagoUnoSolicitudToken
  • ejecutarCobroGrupal(body) — Delega en PagoUnoEjecutarCobroGrupal
  • ejecutarAjustes(body) — Delega en PagoUnoEjecutarAjustes
  • crearEntradaMedioCobro(...) — Crea Medio_de_Cobro_entry__c y actualiza Oportunidad

PagoUnoSolicitudToken / CobrarPagoUnoSolicitudToken

Tokeniza los datos de la tarjeta de crédito enviando un POST a la API de Pago Uno. Retorna un token único de la sesión de cobro.

PagoUnoEjecutarCobroGrupal / CobrarPagoUnoEjecutarCobro

Ejecuta el cobro grupal usando el token generado. Interpreta la respuesta: APROBADA, DENEGADA o ADVERTENCIA. Si es APROBADA, retorna la referencia externa y el ID de transacción.

PagoUnoEjecutarAjustes / CobrarPagoUnoEjecutarAjustes

Realiza un ajuste de cobro cuando el monto cobrado no coincide exactamente con el monto esperado (diferencias de centavos o comisiones).

CalloutControllerPagoUno

Clase base para las llamadas HTTP a Pago Uno. Gestiona autenticación y endpoints usando Named Credentials o configuración custom.

⚙ Clases Apex — Validación CBU

CBUValidation

Realiza un callout a un webservice externo para validar que un CBU pertenece al titular según el CUIT/CUIL ingresado. Retorna 'COINCIDE' si la validación es exitosa o un mensaje de error en caso contrario.

  • callWebService(cbu, cuit) — Llamada HTTP al servicio de validación
El servicio externo de validación CBU requiere que la Named Credential correspondiente esté configurada en el org.

⚙ Clases Apex — Alta de Socios

procesarAlta

Clase central del proceso de alta en el sistema AMTAE. Expone dos métodos principales:

  • procesarTitular(opportunityId) — Construye el DTO del titular desde la Oportunidad y sus datos de Account, y realiza el callout al webservice de AMTAE para dar de alta. Retorna JSON con status y lista de adherentes a procesar.
  • procesarAdherente(adherenteId) — Procesa el alta de un Account adherente vinculado al titular.

DTOSocioAmtaeWS

Data Transfer Object que mapea los campos de Salesforce (Account, Opportunity) a la estructura requerida por el webservice de AMTAE para el alta de socios.

enviarEmailConAlta

Envía un email con el comprobante de alta adjunto tras completarse el proceso de incorporación del socio.

⚙ Clases Apex — Integración CRM AMTAE

Conjunto de clases para recuperar datos del sistema CRM interno de AMTAE y sincronizarlos con Salesforce.

RetrieveDataSistemaAmtae

Clase principal que realiza llamadas al webservice del CRM AMTAE para obtener datos de socios (titulares y adherentes) en un rango de fechas dado.

BatchRetrieveCRMTitularesSistemaAmtae

Batch (Database.Batchable) que recupera y sincroniza los socios titulares desde el CRM AMTAE. Actualiza campos de Account como estado del socio, plan, organismo, filial, etc.

BatchRetrieveCRMAdherentesSistemaAmtae
